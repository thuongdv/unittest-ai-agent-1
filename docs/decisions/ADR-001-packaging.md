# ADR-001: Multi-Runtime Packaging and Canonical Instruction Architecture

- **Status:** Accepted
- **Date:** 2026-10-20
- **Context:** [docs/runtime-compatibility.md](../runtime-compatibility.md)

## Context and Problem Statement

We are building four unit testing AI agents (`codebase-analyzer`, `unit-test-generator`, `unit-test-reviewer`, and `unit-test-failure-analyzer`) that must:

1. Run across four distinct AI coding runtimes: **Claude Code**, **OpenAI Codex CLI**, **Gemini CLI**, and **GitHub Copilot (VS Code Agent Mode)**.
2. Contain **zero helper scripts** (no JS, TS, Python, or Bash install scripts).
3. Avoid duplicating the core agent prompt logic across four different runtime directories.
4. Ensure `unit-test-reviewer` runs in a **fresh, isolated context** (via a subagent where supported) so it does not inherit reasoning bias from `unit-test-generator`.
5. Be installable into any target repository using simple file copy commands (`cp -r`).

## Decision Drivers

- **Single Source of Truth:** Updating a rule, schema field, or language reference table must happen in one place (`agents/<agent-name>.md`), never in four copies.
- **No Install Script Constraint:** Users must be able to install the agents into their target project by copying directories without running a build or transformation script.
- **Uniform Slash-Command UX:** Users should invoke `/codebase-analyzer`, `/unit-test-generator`, `/unit-test-reviewer`, and `/unit-test-failure-analyzer` (or `$<agent>` in Codex Skills) consistently.
- **Fresh-Context Reviewer:** The packaging must wire `unit-test-reviewer` to each runtime's native subagent mechanism.

## Considered Options

### Option 1: Duplicate Full Prompts in Every Runtime Directory

Store full copies of each agent in `.claude/commands/`, `.agents/skills/`, `.gemini/commands/`, and `.github/prompts/`.

- **Pros:** Self-contained per runtime.
- **Cons:** Violates the "no duplicated content" requirement; high risk of drift across 4 runtimes × 4 agents = 16 files.

### Option 2: Canonical `agents/` + Thin Per-Runtime Wrappers (Chosen)

Store the full instructions once per agent in `agents/<agent>.md` (installed into `.unit-test-agent/agents/<agent>.md` in the target repo, along with `schemas/` in `.unit-test-agent/schemas/`). Provide thin 5–15 line wrapper files under `runtimes/<runtime>/` that instruct the runtime to load `.unit-test-agent/agents/<agent>.md` and pass the user's arguments.

- **Pros:** Zero duplication of core instructions; honors every runtime's native command/skill/subagent format; trivial `cp -r` installation.
- **Cons:** Requires copying two folders into the target repo (`.unit-test-agent/` + the chosen runtime's dot-folder).

### Option 3: `SKILL.md` Only (`agents/` as `.agents/skills/`)

Rely exclusively on `.agents/skills/<agent>/SKILL.md` for all four runtimes.

- **Pros:** Single directory.
- **Cons:** Gemini CLI's explicit `/<command>` UX works best with `.gemini/commands/*.toml`, Claude Code and Copilot need `.claude/agents/` and `.github/agents/` for subagent context isolation, and path conventions for `SKILL.md` still vary slightly (`.claude/skills/` vs `.agents/skills/` vs `.github/skills/`).

## Decision

We adopt **Option 2: Canonical `agents/` + Thin Per-Runtime Wrappers**.

### 1. Canonical Files in This Repository

```text
agents/
├── codebase-analyzer.md
├── unit-test-generator.md
├── unit-test-reviewer.md
└── unit-test-failure-analyzer.md
schemas/
├── project.schema.json
├── generation.schema.json
├── review.schema.json
├── failure-analysis.schema.json
└── failure-repair.schema.json
```

### 2. Target Repository Installed Layout

When a user installs the agents into their target repository, `.unit-test-agent/` holds both the canonical assets (`agents/`, `schemas/`) and the generated state (`project.json`, `runs/`):

```text
<target-repo>/
├── .unit-test-agent/
│   ├── agents/                  # Copied from this repo's agents/
│   │   ├── codebase-analyzer.md
│   │   ├── unit-test-generator.md
│   │   ├── unit-test-reviewer.md
│   │   └── unit-test-failure-analyzer.md
│   ├── schemas/                 # Copied from this repo's schemas/
│   │   └── *.schema.json
│   ├── project.json             # Generated by codebase-analyzer
│   └── runs/                    # Generated per run
│       └── <run-id>/
│           ├── generation.json
│           ├── review.json
│           ├── failure-analysis.json
│           └── failure-repair.json
├── .claude/                     # (If using Claude Code: copied from runtimes/claude/.claude)
├── .agents/                     # (If using Codex CLI: copied from runtimes/codex/.agents)
├── .gemini/                     # (If using Gemini CLI: copied from runtimes/gemini/.gemini)
└── .github/                     # (If using GitHub Copilot: copied from runtimes/copilot/.github)
```

### 3. Thin Wrapper Design per Runtime

1. **Claude Code (`runtimes/claude/.claude/`):**
   - `commands/codebase-analyzer.md`, `commands/unit-test-generator.md`, `commands/unit-test-failure-analyzer.md`: Thin Markdown command wrappers referencing `@.unit-test-agent/agents/<agent>.md` and passing `$ARGUMENTS`.
   - `commands/unit-test-reviewer.md` + `agents/unit-test-reviewer.md`: The slash command delegates execution to the `unit-test-reviewer` subagent so the review runs in a fresh, isolated context window.

2. **OpenAI Codex CLI (`runtimes/codex/.agents/` & `.codex/`):**
   - `.agents/skills/<agent>/SKILL.md`: YAML frontmatter (`name`, `description`) instructing Codex to read and follow `.unit-test-agent/agents/<agent>.md` with the user's arguments.
   - `.codex/agents/unit-test-reviewer.md`: Subagent definition for fresh-context review.

3. **Gemini CLI (`runtimes/gemini/.gemini/`):**
   - `commands/<agent>.toml`: Uses Gemini CLI's native `@{.unit-test-agent/agents/<agent>.md}` file inclusion and `{{args}}` interpolation.
   - `agents/unit-test-reviewer.md`: Subagent persona for isolated review context.

4. **GitHub Copilot (`runtimes/copilot/.github/`):**
   - `prompts/<agent>.prompt.md`: YAML frontmatter (`mode: 'agent'`) referencing `[instructions](../../.unit-test-agent/agents/<agent>.md)`.
   - `prompts/unit-test-reviewer.prompt.md` + `agents/unit-test-reviewer.agent.md`: Uses `tools: ['agent/runSubagent']` to execute the review in an isolated subagent context.

## Consequences

- **Positive:** Zero prompt duplication; 100% compliant with the "no helper code / copy-based install" constraint; native support for fresh-context review in all four runtimes.
- **Negative:** Users run two `cp -r` commands during initial setup (one for `.unit-test-agent/{agents,schemas}`, one for their runtime wrapper folder), which will be clearly documented in `README.md` (F10).
